# resume-formatter-service

FastAPI backend that reformats a resume's content into another resume's visual template,
via a multi-pass Gemini + Playwright pipeline.

## Stack

- **FastAPI** — HTTP API
- **Gemini** (`google-genai`) — vision-based design-token extraction + HTML generation
- **PyMuPDF (fitz)** — PDF parsing, rasterization, design-token extraction (color/typography/logo)
- **Playwright/Chromium** — HTML → PDF rendering (primary), **wkhtmltopdf** as fallback
- **Cloudinary** — template storage
- **LibreOffice** — DOCX ⇄ PDF conversion where needed

## Layout

- `app/main.py` — app entry, mounts the resume router
- `app/routes/resume.py` — endpoints: template CRUD, LLM settings CRUD, `/generate-resume`, `/format`, `/generate-resume-html`, `/health`
- `app/controllers/resume_controller.py` — orchestrates the pipeline: parse → Gemini → render
- `app/services/` — parsers (`pdf_parser.py`, `docx_parser.py`), LLM (`gemini_service.py`, `llm_client.py`, `browser_pool.py`), output (`pdf_generator.py`, `template_render_compare.py`), storage (`cloudinary_service.py`, `template_store.py`)

## Core pipeline (`gemini_service.py`)

1. **Pass 1 (vision)** — rasterize template at `VISION_DPI=220`, send to Gemini → design tokens (bbox %, colors, spacing, typography). Content text explicitly ignored — design only.
2. **Pass 2 (HTML generation)** — merged tokens + template images + target resume content → full HTML, forced `<table>` scaffold for cross-renderer consistency.
3. **Pass 3-6 (render-compare loop, optional, max 2 iterations)** — render → rasterize at `COMPARE_DPI=150` → pixel-diff score vs template → if similarity < `SIMILARITY_THRESHOLD=0.92`, regenerate with measured corrections.

Color/typography authority is PyMuPDF (exact bytes), not Gemini vision — prevents hallucinated colors. Logos are spliced in as real image bytes post-generation, never regenerated by the LLM.

## Setup

```bash
pip install -r requirements.txt
playwright install chromium
```

Requires `GOOGLE_API_KEY` (and Cloudinary credentials, if using template storage) — see `app/config.py` / `.env`.

```bash
uvicorn app.main:app --reload
```

## Memory / reliability notes (deployment target: AWS t3.micro, 1GB RAM)

A 1GB instance has to fit FastAPI + Gemini request buffers + PyMuPDF + Chromium (+ occasionally
LibreOffice) simultaneously, so the service is tuned conservative-first. Changes made so far:

| Change | Why |
|---|---|
| Persistent Chromium (`browser_pool.py`) | Was launching/killing a full Chromium process per render (100-300MB spike each time). Now one process, reused for the app's lifetime. |
| Split `VISION_DPI` (220) from `COMPARE_DPI` (150) | The render-compare loop's internal pixel-diff scoring doesn't need print-quality resolution — only what Gemini actually sees does. ~54% smaller compare-loop images, zero accuracy impact on Gemini's input. |
| `MAX_CONCURRENT_PIPELINES` semaphore (default **1**) | Caps how many full pipelines run at once — without it, N concurrent requests = N pipelines' worth of RAM stacked simultaneously. This is the main defense against OOM under load; excess requests queue instead of piling up memory. |
| Deduplicated image decodes (`template_render_compare.py`) | `compute_similarity_score` used to re-decode the same generated PNG up to ~7x across its sub-checks. Now decoded once (RGB + grayscale) and shared. |
| Streamed Cloudinary download | Was buffering the full HTTP response before writing to disk. |
| Dropped unused deps (`docx2pdf`, `anthropic`) | Confirmed unused — smaller install footprint. |

**Non-negotiables** (do not regress while further optimizing): Gemini's vision input stays at
220 DPI / PNG, `MAX_ITERATIONS` stays at 2 — both are accuracy-critical, not just performance knobs.

### Still outstanding

- **RSS benchmark** — none of the above has been measured yet. Run the service under `docker run -m 1g` (or on a real t3.micro), fire 1 / 2 / 4 concurrent requests against `/generate-resume`, and record idle vs peak RSS at each level plus request latency. This is the actual proof the service fits in 1GB, not an estimate.
- **Swap** (1-2GB) — OS-level safety net on the instance itself (`fallocate`/`mkswap`/`swapon`), not app code. Doesn't replace the above; just turns an occasional spike into a slow request instead of an OOM kill.
- `scipy` is imported by `template_render_compare.py` but missing from `requirements.txt` — pre-existing gap, needs adding.
